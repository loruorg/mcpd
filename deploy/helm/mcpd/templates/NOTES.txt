mcpd {{ .Chart.AppVersion }} is installed as {{ include "mcpd.fullname" . }}.

Reach the interface from your machine:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "mcpd.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}

Then open http://localhost:{{ .Values.service.port }}. The interface is static
markup; the query API behind it enforces the read key.

Point an agent at it from inside the cluster:

  MCPD_ENDPOINT=http://{{ include "mcpd.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}
  MCPD_API_KEY=<one of your ingest keys>

The Service is plain HTTP. mcpd does not terminate TLS; put it behind your
ingress or your mesh if the traffic leaves the cluster.

{{- if .Values.keys.existingSecret }}

keys.existingSecret is set, so this chart did not write the admin keys. If that
Secret has no admin-keys entry, the daemon accepts the read keys for admin work:
every read key can delete traces, erase subjects and read the audit log. Add an
admin-keys entry with its own key (`openssl rand -hex 32`) if it has none.
{{- else }}

keys.admin is empty, so the daemon accepts the read keys for admin work: every
read key can delete traces, erase subjects and read the audit log. Set
keys.admin to its own key (`openssl rand -hex 32`) and upgrade the release.
`mcpd doctor` reports the same thing until you do.
